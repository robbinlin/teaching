## 講授重點

### 1. 粒度與鍵

**粒度**是「一列代表什麼」。主資料集一列是一位學生。都市化分層表一列是一個縣市。合併之前先說出兩張表各自的粒度，以及用哪個欄位（鍵）對應。

合併前對每張表做一件事：檢查鍵是否唯一。

```r
urban_level |> count(county) |> filter(n > 1)   # 應回傳 0 列
```

### 2. 四種合併與列數規則

| 合併 | 保留誰 | 多對一時的列數 |
|---|---|---|
| inner | 兩邊都有的 | 小於或等於左表 |
| left | 左表全部 | 等於左表 |
| right | 右表全部 | 大於或等於右表 |
| full | 兩邊全部 | 大於或等於較大者 |

最常用的是把縣市層級的資料併到學生層級（多對一的 left join）。規則只有一條：**合併後列數必須等於左表列數**。變多，表示右表的鍵不唯一。

可以讓程式替你檢查：

```r
left_join(survey, urban_level, by = "county",
          relationship = "many-to-one")
```

```python
survey.merge(urban_level, on="county", how="left", validate="m:1")
```

違反時程式會報錯，不會默默產生多餘的列。

### 3. 多對多：SAS 的 DATA step 與 SQL 給出不同答案

課程範例中，`alfa` 與 `beta` 兩張表的 `A25` 各有三筆。

| 做法 | 結果列數 | 原因 |
|---|---|---|
| `DATA; MERGE alfa beta; BY id;` | 4 | 同一鍵內依序一對一配對 |
| `PROC SQL` inner join | 10 | 同一鍵內兩兩配對：1 + 3×3 |

兩段程式都沒有錯誤訊息。請 AI 把 DATA step 改寫成 SQL，或從 SAS 翻成 R，結果的列數就可能改變。多對多幾乎都不是你要的，遇到時先回頭問：其中一張表的粒度是否弄錯。

### 4. 沒對上的列

left join 之後，右表欄位為遺漏的列，就是沒對上的列。用 anti join 把它們找出來：

```r
anti_join(survey, urban_level, by = "county") |> count(county)
```

沒對上的常見原因：代碼表漏列、文字前後有空白、大小寫或全半形不同、數值與文字型態不同。

### 5. 彙總的分母

課程既有程式計算各縣市規律運動比例：

```sql
select county,
       sum(regular = 1) / count(*) as regular_pct
from survey4
group by county;
```

`count(*)` 計算所有列，包含 `regular` 為遺漏的人。`count(regular)` 只計算非遺漏。兩者的差別就是「沒回答的人算不算分母」。這個決定應該出現在規格書，不該由寫 SQL 的人或模型臨時決定。

### 6. DuckDB：直接對 CSV 下 SQL

```sql
select county, count(*) as n
from 'data108.csv'
group by county
order by county;
```

不需要先建資料庫。適合讓 AI 寫查詢、自己逐步驗證列數。
