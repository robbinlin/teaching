# 第 3 週　AI 協作分析工作流與分析規格書

## 本週要回答的問題

怎麼下指令，才能讓兩個人、兩個模型拿到同一題時，算出同一個數字？

## 時間配置

| 時段 | 內容 |
|---|---|
| 第 1 節 | 五步工作流；對話式與可執行環境的差別 |
| 第 2 節 | 分析規格書；示範 |
| 第 3 節 | 課堂任務：寫規格、交換執行 |

## 講授重點

### 1. 五步工作流

| 步驟 | 人做什麼 | AI 做什麼 | 留下什麼 |
|---|---|---|---|
| 規格 | 寫下問題、定義、規則 | 指出規格中的模糊處 | 規格書 |
| 計畫 | 核可或修改 | 提出分析步驟與表格外殼 | 分析計畫 |
| 執行 | 監看紀錄 | 寫程式並執行 | 程式、輸出、紀錄檔 |
| 驗證 | 設計檢查並判定 | 執行檢查、擔任第二審查者 | 驗證紀錄 |
| 報告 | 決定結論與限制 | 起草文字與圖表 | 可重跑的報告 |

第一週的示範直接從一句話跳到執行，略過了規格與計畫，所以每次結果不同。

### 2. 兩種 AI 使用方式

| | 純對話 | 可執行程式的環境 |
|---|---|---|
| 模型如何得到數字 | 依語言規律生成 | 執行程式後讀取輸出 |
| 數字可信嗎 | 不可作為結果 | 可以，但程式仍須審查 |
| 判斷方式 | 沒有程式與輸出 | 能看到程式碼與執行結果 |

本課程只接受第二種產生的數字。模型說「平均為 3.42」而沒有對應的程式輸出，這個數字不存在。

### 3. 分析規格書

一頁，八個欄位。

| 欄位 | 內容 | 以「都市化與規律運動」為例 |
|---|---|---|
| 研究問題 | 一句話，標明問題類型 | 描述：各都市化層級學生的規律運動比例 |
| 資料 | 檔名、版本、列數 | `data108.csv`，SRDA 釋出版 |
| 分析母體 | 納入與排除條件 | 全部受訪者；排除縣市代碼遺漏者 |
| 變項定義 | 題號、編碼、衍生規則 | 規律運動＝每週運動天數達標且運動時會流汗會喘；兩題任一遺漏則為遺漏 |
| 遺漏值規則 | 編碼與處理方式 | -1 視為遺漏；採完整個案；報告排除人數 |
| 方法 | 統計量與檢定 | 各層比例與 95% 信賴區間；趨勢檢定 |
| 輸出 | 表格外殼 | 列：六個都市化層級；欄：人數、規律運動人數、比例、信賴區間 |
| 驗收條件 | 怎樣算做對 | 各層人數加總等於分析母體；衍生變項與原始題目的交叉表無非預期組合 |

**表格外殼**是先畫好、只缺數字的空白表格。它迫使你在看到結果之前決定要報告什麼。

**規格書的測試**：把同一份規格交給兩個人或兩個模型，表格裡的數字應該相同。不同，表示規格還有沒寫到的決定。

### 4. 可重現的最低要求

每次分析保存下列六樣：資料版本、程式、輸出、對話或執行紀錄、套件版本（R 用 `sessionInfo()`）、亂數種子。

### 5. 資料治理

- 資料能否上傳到雲端服務，由資料的使用約定決定，不由方便與否決定。
- 不能上傳時的做法：把變項清單與型態交給 AI，附上幾筆自行編造的合成資料，請它寫程式；程式在本機執行，只把彙總後的輸出貼回對話。
- 使用可在本機執行的程式代理時，確認它不會把資料內容送出。

## 課堂示範

把上表的規格書交給 AI 助理，請它先指出規格中仍不明確之處，再提出計畫，然後執行。把結果與第一週的兩份輸出並排。

## 課堂任務（60 分鐘）

1. 每組為第 2 週選定的描述性問題寫一頁規格書（25 分鐘）。
2. 與另一組交換。拿到別組規格書的組，不可詢問原作者，直接交給 AI 執行（20 分鐘）。
3. 兩組比對數字。列出不一致的每一處，回頭在規格書補上缺漏的決定（15 分鐘）。

## 檢核清單

- [ ] 每個衍生變項都寫出遺漏時的處理方式
- [ ] 分母是誰寫清楚了
- [ ] 表格外殼在執行前已經畫好
- [ ] 驗收條件至少有一條可以用程式檢查

## 搭配工具

AI 助理（可執行程式）；選用：Claude Code 等本機程式代理。

## 課後作業（驗證紀錄 2）

繳交修訂後的規格書，以及修訂前後兩次執行結果的對照。說明補上了哪些決定、數字因此改變多少。

## 教師備註

- 交換執行時最常出現的差異是分母。讓學生自己發現，不要先提示。
- 規格書範本另以一頁空白表格發給學生，期末專案沿用同一格式。
