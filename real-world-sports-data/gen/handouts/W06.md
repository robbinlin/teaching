# 第 6 週　驗證與除錯

## 本週要回答的問題

程式跑完了，沒有錯誤訊息，圖表也很漂亮。你怎麼知道結果是對的？

## 時間配置

| 時段 | 內容 |
|---|---|
| 第 1 節 | 六類錯誤；三個真實案例 |
| 第 2 節 | 七種驗證技術 |
| 第 3 節 | 找錯競賽 |

## 講授重點

### 1. 六類錯誤

| 類別 | 例子 | 會不會有錯誤訊息 |
|---|---|---|
| 資料 | 遺漏碼被當數值、重複紀錄、代碼表過期 | 不會 |
| 定義 | 衍生變項的規則與規格不符、分母不對 | 不會 |
| 方法 | 檢定用錯、忽略權重、模型放錯變項 | 不會 |
| 執行 | 條件永遠不成立、合併後列數膨脹 | 通常不會 |
| 解讀 | 把相關寫成因果、把 OR 當成倍數 | 不會 |
| AI 特有 | 未執行程式就報數字、捏造引用、擅自更改定義 | 不會 |

會讓程式停下來的錯誤最容易處理。本週處理的是不會停下來的那些。

### 2. 案例一：都市化分層

課程既有程式：

```sas
if county=1 then urban=1;
else if county in (18,1,19,20) then urban=2;
else if county in (7,3,10,4,5,17,21) then urban=3;
else if county in (8,9,13,12,14,22) then urban=4;
else if county in (6,11) then urban=5;
else if county in (16,15) then urban=6;
```

請學生先自己讀，回答兩題：`county=1` 會被分到哪一層？`county=2` 會被分到哪一層？

- `county=1` 同時出現在第一、二行。第一行先成立，第二行的 1 永遠不會被用到。這可能是筆誤，原本想寫的是另一個代碼。
- `county=2` 不在任何一行，`urban` 為遺漏。後續的 `proc freq` 預設不顯示遺漏，這個縣市的學生就從分析中消失，沒有任何訊息。

一個交叉表就能看出來：

```sas
proc freq data=survey4;
  tables county*urban / missing norow nocol nopercent;
run;
```

每個縣市應該只落在一個層級，而且沒有任何縣市落在遺漏。請對照編碼簿確認各代碼對應的縣市。

### 3. 案例二：`else` 把遺漏變成 0

```sas
if b9_1a>=4 and b9_2=1 then regular=1;
else regular=0;
```

兩題都沒回答的學生，條件不成立，被歸為「不規律運動」。規律運動比例因此被低估，低估的幅度取決於遺漏的人數。修正方式是先處理遺漏：

```sas
if missing(b9_1a) or missing(b9_2) then regular=.;
else if b9_1a>=4 and b9_2=1 then regular=1;
else regular=0;
```

### 4. 案例三：軸標籤寫百分比，畫的是人數

```sas
proc sgplot data=survey4;
  vbar urban / response=regular datalabel;
  yaxis label="Exercise Percentage (%)";
run;
```

`vbar` 搭配 `response=` 時，預設統計量是加總。`regular` 是 0/1，加總就是規律運動的人數。人數最多的層級柱子最高，與比例無關。要畫比例須加上 `stat=mean`。圖上的數字若是幾千幾萬，就不可能是百分比。

### 5. 七種驗證技術

| 技術 | 做法 | 抓得到什麼 |
|---|---|---|
| 衍生變項交叉表 | 原始變項 × 衍生變項，包含遺漏 | 案例一、二 |
| 列數帳 | 讀入 → 每次排除 → 分析樣本，逐步記錄人數 | 靜默刪列、合併膨脹 |
| 斷言 | 在程式中寫下必須成立的條件，不成立就停止 | 之後資料或程式改動造成的錯誤 |
| 手算一格 | 挑表格中的一格，用最原始的方式重算 | 分母、統計量選錯（案例三） |
| 合理性檢查 | 數值範圍、加總、與已知統計比較 | 單位錯、量級錯 |
| 獨立重做 | 換一種語言或換一個模型，從規格書重做 | 各種實作錯誤 |
| 已知答案測試 | 用自己造的小資料，答案事先算好 | 邏輯錯誤 |

斷言的寫法：

```r
stopifnot(nrow(merged) == nrow(survey))
stopifnot(!any(is.na(survey4$urban)))
```

### 6. 請 AI 當審查者

可以把程式與輸出交給另一個模型，請它找問題。它會提出一些真的問題，也會提出一些不存在的問題。它的每一項意見都是待查證的線索，判定仍由你做，而且要有輸出作為證據。

不要請同一個對話中的同一個模型審查自己剛寫的程式，它傾向同意自己。

## 課堂任務：找錯競賽（70 分鐘）

教師發下一份兩頁的短報告、對應程式與資料。報告由 AI 產生，內含五個植入的錯誤，分屬資料、定義、執行、方法、解讀五類。

- 每組找出錯誤，每一項須附上證明它是錯誤的輸出。
- 只指出「這裡怪怪的」而沒有證據，不計分。
- 把正確的做法誤指為錯誤，扣分。
- 結束後各組輪流報告一項，其他組可以質疑。

## 檢核清單（期中評分以此為基礎）

- [ ] 每個衍生變項都有一張包含遺漏的交叉表
- [ ] 有一份從讀入到分析樣本的列數帳
- [ ] 每張圖至少有一個數字與表格核對過
- [ ] 至少一個關鍵數字由第二條路徑重現
- [ ] 每一項審查意見都附有輸出作為證據

## 搭配工具

R 或 SAS；第二個 AI 助理（審查者）；JASP（獨立重做）。

## 課後作業（驗證紀錄 5）

回到第 3 週的規格書與執行結果。對它套用本週的檢核清單，繳交五項檢查的輸出。若發現問題，說明原因並更新結果。
